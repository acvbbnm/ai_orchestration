# 엔진 사용법 — AI DEV 자동개발 + 학습 엔진

> 로컬에 설치한 오케스트레이터([ai-dev-director](https://github.com/digilogd-cmd/ai-dev-director), MIT)를 이 작업 폴더에서 쓰는 방법.
> **엔진 본체는 이 레포에 포함되어 있지 않다** — `C:\Users\user\ai-dev-director-inspect`에 별도 설치.
> 엔진을 실험·분석한 문서는 [`AI오케스트레이션/`](../AI오케스트레이션/README.md)에 있다.

AI CLI들을 한 회사처럼 돌려 **목표 한 줄 → 검증된 코드 → 학습 브리핑**까지 이어주는 개인 작업 엔진.

## 빠른 시작
1. 바탕화면 **AI엔진 시작** 또는 **`START.bat`**를 더블클릭하면 [TRINITY 콘솔](http://127.0.0.1:8081)이 열린다.
2. 콘솔 상단의 **프로젝트**에서 `바탕화면\프로젝트` 아래 작업 폴더를 선택한다. 새 작업은 새 하위 폴더를 만들어 선택하면 된다. 기존 설정에서는 빈 폴더를 선택하면 로컬 Git 저장소를 초기화한다.
3. 입력창에서 **개발** 또는 **조사**를 선택한다. 개발은 HEAD → BUILDER → 검증 → REVIEWER 루프를 실행한다. 조사는 독립 조사 → 교차 검토 → 종합을 한 번 수행해 보고서를 저장한다.
4. 개발 후 **학습 브리핑**을 만들 수 있다.
   ```powershell
   powershell mentor\learn.ps1 -Project "C:\path\to\your-project"
   ```
   → 그 프로젝트에 `LEARNING.md`가 생긴다.
5. 끄려면 **`STOP.bat`** 또는 콘솔의 **시스템 중지**를 사용한다.

## 프로젝트별 결과

- 개발에서 검증을 통과한 작업은 자동 적용 설정에 따라 선택한 프로젝트에 반영된다. 사용자 편집과 충돌하면 적용을 보류한다. 미션 요약과 단계 기록은 `director-records/development/<미션 ID>/`에 저장된다.
- 조사 기록은 `director-records/research/<세션 ID>/`에 저장된다. `REPORT.md`, 종합 결과, 호출 기록과 연구자별 프롬프트·응답을 확인할 수 있다. 조사 실행에는 구성된 세 CLI가 필요하다.
- 프로젝트 코드와 함께 공유할 기록을 검토한 뒤 각 프로젝트의 Git에 직접 추가할 수 있다.

## 개발 HEAD 세션 유지

Codex가 HEAD를 맡으면 프로젝트별 CLI 세션 ID를 엔진 DB에 저장한다. 다음 대화, 미션의 다음 계획, 구현 결과 판정에서 그 ID로 세션을 재개한다. A → B → A로 프로젝트를 바꾸면 A의 기존 콘솔 대화도 다시 연다.

HEAD는 호출마다 프로젝트에 있는 `PROJECT.md`와 `TASK.md`를 각각 최대 6,000자까지 읽어 현재 입력에 포함한다. 문서가 있으면 설계와 작업 상태를 여기에 적어 둘 수 있다. 프로젝트 문서 자동 생성·갱신과 Claude Builder·Antigravity Reviewer 세션 유지는 후속 구현 항목이다.

구현 결과가 프로젝트에 적용된 이후의 새 미션은 현재 프로젝트 파일을 기준으로 시작한다. 적용 전 작업본을 이어갈 때는 해당 작업본의 현재 내용을 사용한다. 실행 기록에는 Codex 세션 ID와 재개 여부를 남긴다. 저장된 CLI 세션이 삭제됐다고 Codex가 명시적으로 응답하면 현재 요청과 프로젝트 문서를 넣어 새 세션을 만들고 복구 사실을 기록한다.

## MCP 조사 자료

엔진의 `config.yaml`에서 해당 프로젝트의 `research_resources`에 로컬 Streamable HTTP MCP 서버의 URL과 읽을 텍스트 리소스 URI를 적는다.

```yaml
projects:
  "C:/Users/user/Desktop/프로젝트/문서조사":
    research_resources:
      - url: "http://127.0.0.1:8765/mcp"
        uri: "docs://project/overview"
```

콘솔에서 **조사**를 보내면 엔진이 지정한 리소스를 읽어 세 연구자의 공통 자료에 넣는다. 예시 서버 주소와 URI는 실제 로컬 서버의 값으로 바꿔야 한다.

## 흐름
```
목표 → HEAD(Codex) → BUILDER(Claude) → 테스트(pytest) → REVIEWER(Antigravity) → HEAD 판정
                                                                                    │
                                                                         MENTOR(agy) → 학습 브리핑
```
역할별 실제 호출 방식과 단계마다 오가는 JSON은 [AI오케스트레이션 2장](../AI오케스트레이션/02_오케스트레이션_실제동작_증적.md) 참고.
