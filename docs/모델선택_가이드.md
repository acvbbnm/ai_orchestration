# 모델 선택 가이드

## 핵심 2가지
1. **모델은 엔진(director)이 아니라 각 CLI 안에서 정한다.** 엔진은 모델 플래그를 넘기지 않는다.
   - claude 모델 → `claude` 실행 후 `/model`
   - codex 모델 → codex 설정
   - agy 모델 → Antigravity 설정 (한도 초과 시 자동으로 가벼운 모델로 강등됨)
2. **같은 공급자를 쓰는 역할은 같은 모델을 공유한다.**
   - 지금 HEAD·BUILDER 둘 다 claude → 둘은 같은 claude 모델을 쓴다.

## 역할별 권장 성향

| 역할 | 권장 | 이유 |
|---|---|---|
| HEAD | 강한 사고/추론 | 계획·판정이 핵심 |
| BUILDER | 강한 코딩 | 품질 = 전체 결과·토큰 좌우. 낮추면 재시도 루프↑ 로 오히려 손해 |
| REVIEWER | 중상급 | 버그 탐지. 너무 낮추면 미탐 |
| MENTOR | 설명 잘하는 모델 | 학습 브리핑 품질 |

> **코딩 vs 사고력**: 쉬운 코드는 모델 등급 차이가 작지만, 복잡한 코드는 코딩=사고력이라 등급이 올라갈수록 좋아진다. BUILDER는 완전히 낮추지 말 것.

## HEAD와 BUILDER 모델을 다르게 주고 싶다면
같은 claude라 지금은 공유된다. 분리하려면 **공급자를 나눠야** 한다:
- 예) `config.yaml` 에서 HEAD=codex(강한 사고), BUILDER=claude(코더)
- 단 REVIEWER가 HEAD와 같은 공급자가 되면 독립성 경고(`REDUCED_INDEPENDENCE`)가 뜬다 (치명적 아님).

## 토큰 아끼는 법 (모델 낮추기보다 이걸로)
1. **프로필** `quick / standard / deep` — 단계·재시도 상한 (quick = 최소)
2. **스코프 캡** — `config.yaml` 의 `safety.max_files_changed`, `max_diff_lines`
3. **역할 분산** — 여러 공급자에 나눠 한 구독이 빨리 마르지 않게
4. **failover** — 한 공급자 한도 소진 시 자동으로 다른 CLI로 전환 (자동)
