## 🎯 이번에 만든 것
일시적 장애(네트워크 타임아웃, 외부 API 5xx 등) 발생 시 비즈니스 로직을 수정하지 않고 재시도를 적용할 수 있는 데코레이터 유틸리티(`util/retry.py`)를 구현했다.

## 📚 핵심 개념 (3~5개, 우선순위 순)
- **[인자를 받는 데코레이터 팩토리와 클로저(Closure)]** — `util/retry.py:6-19` — 함수가 3단(`retry` → `decorator` → `wrapper`)으로 중첩되는 이유는 데코레이터 자체에 설정값(`times`, `base`)을 전달하고 이를 내부 스코프에 묶어두기 위함이다.
  - 💬 **면접 한 줄**: "데코레이터에 동적 설정을 주입하기 위해 팩토리 함수가 클로저로 설정값을 캡처하고 실제 데코레이터를 반환하도록 3단 구조로 설계했습니다."
- **[지수 백오프와 지터(Exponential Backoff + Jitter)]** — `util/retry.py:17` — 고정 간격으로 재시도하면 장애 복구 시점에 모든 클라이언트의 요청이 동시에 몰리는 'Thundering Herd' 현상이 발생하므로, 대기 시간을 지수적으로 늘리고 난수(Jitter)를 더해 트래픽을 분산한다.
  - 💬 **면접 한 줄**: "장애 전파와 동시 재시도 폭주(Thundering Herd)를 막기 위해 대기 시간을 $2^n$으로 늘리는 지수 백오프에 랜덤 지터를 결합했습니다."
- **[예외 필터링과 원본 스택트레이스 보존 (`raise`)]** — `util/retry.py:6`, `util/retry.py:14-16` — 모든 에러를 무조건 재시도하지 않도록 튜플로 대상 예외를 제한하고, 최종 실패 시 `raise exc` 대신 단독 `raise`를 써서 최초 발생 지점의 Traceback을 훼손하지 않고 그대로 올린다.
  - 💬 **면접 한 줄**: "재시도 가능한 예외만 튜플로 주입받아 처리하고, 최종 실패 시에는 인자 없는 `raise`를 사용해 원본 콜스택을 보존했습니다."
- **[메타데이터 보존 (`@functools.wraps`)]** — `util/retry.py:9` — 래퍼 함수가 원본 함수를 감싸면 함수명(`__name__`)과 독스트링(`__doc__`)이 `wrapper`로 덮어써져 디버깅, 로깅, API 문서 자동화가 깨지는 것을 방지한다.
  - 💬 **면접 한 줄**: "데코레이터 적용 후에도 디버깅 및 인트로스펙션 시 원본 함수의 메타데이터가 유지되도록 `functools.wraps`를 적용했습니다."

## 🧭 설계 결정 (1~2개)
- **왜 함수 내부 `try/for` 루프가 아니라 데코레이터인가?**
  - **대안**: 호출하는 함수마다 `for`문과 `try-except`를 직접 작성.
  - **트레이드오프**: 직접 작성하면 흐름이 직관적이지만 비즈니스 로직과 인프라성 에러 처리 코드가 섞이고 중복된다. 데코레이터로 분리하면 호출부 함수를 순수하게 유지(관심사 분리)하고 한 줄(`@retry(...)`)로 재사용할 수 있다.
- **왜 기본 예외(`exceptions=(Exception,)`)를 튜플 인자로 열어두었는가?**
  - **대안**: 내부에서 `except Exception:`으로 하드코딩.
  - **트레이드오프**: `ValueError`나 인증 실패(401) 같은 영구적 오류는 백 번 재시도해도 실패하며 시간만 낭비한다. 호출부에서 `(TimeoutError, ConnectionError)`처럼 일시적(Transient) 오류만 지정할 수 있게 열어두어야 프로덕션에서 안전하다.

## 🎯 너의 성장 포인트 저격
- **파이썬 관용구(Idiom)와 표준 라이브러리 활용** — `util/retry.py:8-10`
  - `@functools.wraps(fn)`과 가변 인자 패스스루(`*args, **kwargs`)의 조합은 파이썬으로 공통 컴포넌트나 도구를 만들 때 가장 기본이 되는 템플릿이다. `util/retry.py:8-13`을 직접 읽고 어떤 함수 시그니처든 투명하게 감싸는 원리를 눈으로 확인하라.
- **프로덕션 에러 처리 디테일** — `util/retry.py:14-16`
  - 파이썬의 `except` 절은 단일 예외 클래스 또는 **예외 클래스들의 튜플**만 받는다. 왜 `util/retry.py:6`에서 `[Exception]`(리스트)이 아니라 `(Exception,)`(1-원소 튜플)로 선언했는지, 그리고 `util/retry.py:15-16`에서 마지막 시도에 어떻게 루프를 탈출하는지 직접 읽어라.

## 🔧 직접 해볼 것 (1~2개)
1. **`@functools.wraps(fn)` 지우고 확인하기**: `util/retry.py:9`를 주석 처리한 뒤, 아무 함수에나 `@retry()`를 붙이고 `함수이름.__name__`을 출력해봐라. 로거에서 함수명을 찍을 때 왜 문제가 되는지 바로 보인다.
2. **바운더리 케이스 깨뜨려 보기**: `@retry(times=0)`으로 호출하면 함수가 에러를 내는지, 아니면 조용히 `None`을 반환하는지 직접 실행해서 확인하고, 이를 막으려면 어디를 고쳐야 할지 손으로 짜봐라.
