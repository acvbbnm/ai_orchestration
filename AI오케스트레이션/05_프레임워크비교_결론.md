# 05. 프레임워크 비교와 내 용도 결론

## 5.1 세 갈래 — 각자 "세션유지/컨텍스트"를 다르게 푼다

### 갈래 1. 상태영속 프레임워크 (가장 "제대로", 단 API 과금)
- **LangGraph** — 이 분야 정석. **checkpointer**(스레드별 단기: 노드마다 전체 상태 저장, `thread_id`로 재개 — human-in-the-loop·time-travel·장애복구) + **store**(스레드 교차 장기 기억). 백엔드 Sqlite/Postgres. → director의 "콜드스타트"를 **아키텍처로 해결**한 모습.
- **CrewAI** — 2026년 SQLite 체크포인트(`@persist`) + 메모리(단기/장기/엔티티) 추가.
- **AutoGen** — 영속성 약함(수동 save_state), **유지보수 모드** → Microsoft Agent Framework가 후계. 신규 채택 비권장.

→ 공통 약점: **대부분 모델 API 과금** = 내 구독 CLI와 안 맞음.

### 갈래 2. "AI 사무실" 계열 (구조적 컨텍스트 엔지니어링)
- **MetaGPT** — 에이전트가 1:1로 떠들지 않고 **공유 메시지풀**에 산출물(문서·다이어그램)을 올리고 **역할별로 필요한 것만 구독**. director처럼 전부 평탄화하지 않는 게 핵심 — 이게 진짜 컨텍스트 엔지니어링.
- **ChatDev** — 가상 소프트웨어 회사. **chat chain**(정해진 순서) + **memory stream**(누적 대화). 단 "inside-trial memory"(한 작업 안에서만).

→ director의 HEAD/BUILDER/REVIEWER는 ChatDev를 얕게 베낀 것 — **메시지풀·메모리스트림이 빠져** 맥락이 매 스텝 풀린다.

### 갈래 3. CLI-네이티브 병렬 (구독을 살리는 유일한 길)
- **Claude Squad**(smtg-ai, AGPL-3.0) — Claude Code/Codex/Gemini를 **tmux + git worktree**로 각각 독립 작업공간에서 병렬. **각 에이전트가 자체 CLI 세션 유지**(claude `--resume`). 단 **자동 오케스트레이션은 없음 — 내가 지휘**.
- **cmux** — 같은 개념의 macOS 전용 터미널(Ghostty). → Win11은 불가.
- **wmux** — **WSL 없이 Windows 네이티브**로 Claude/Codex/Gemini 병렬. Win11 대안.

## 5.2 director가 "worst of both"인 이유

| | 구독과금 | 세션유지 | 구조적 컨텍스트 |
|---|---|---|---|
| LangGraph/CrewAI | ❌ API | ✅ | ✅ |
| MetaGPT/ChatDev | ❌ API | 일부 | ✅ 메시지풀 |
| Claude Squad/cmux/wmux | ✅ CLI | ✅ CLI세션 | △ worktree+공유파일 |
| **director** | ✅ CLI | ❌ **1회성** | ❌ **파일 평탄화** |

director는 **구독의 장점만 취하고 세션·컨텍스트를 버렸다.** 그리고 결정적으로 — **Claude Code 자체가 이미** 세션유지·컨텍스트 압축·서브에이전트·메모리·MCP를 다 한다. 그러니 **하네스를 새로 만들 게 아니라, 그걸 다 갖춘 하네스를 여러 개 오케스트레이션**하는 게 정석이다.

## 5.3 내 용도 기준 결론

**내 조건**: Win11 + GPT/Claude/Gemini 구독 + IDA/Burp MCP + 바텀업 학습 + 포트폴리오 + **자동 오케스트레이션 불필요**.

> "자동 오케스트레이션 불필요"가 결정적이다 — 그게 director의 **유일한 고유 가치**였기 때문. 그걸 안 쓰면 director는 유지비만 드는 짐이 된다.

| 항목 | director(codex 수정판) | **Claude Squad / 데스크톱앱 세션** |
|---|---|---|
| 세션 연속성 | HEAD만, Builder/Reviewer 콜드스타트 | ✅ 전원 네이티브 |
| Builder JSON 깨짐 | ❌ 미해결 | ✅ 없음(도구로 파일 씀) |
| MCP(IDA/Burp) | △ 커스텀 어댑터 | ✅ 그냥 됨 |
| 유지보수 | ❌ 높음 | ✅ 0 |
| 자동 오케 | ✅(불필요) | ❌(내가 지휘, OK) |
| 바텀업 학습 | △ 탑다운 | ✅ 루프 안에 내가 |
| Windows | ✅ | △ WSL2 또는 wmux/데스크톱앱 |

**결론**:
1. **주 드라이버를 CLI-네이티브로 교체.** 가장 쉬운 건 **지금 쓰는 데스크톱 앱의 세션 기능**(설치 0, Windows 네이티브) — Claude Squad와 거의 같은 걸 준다. 터미널에서 tmux 격자로 직접 통제하고 싶으면 **WSL2 + Claude Squad**(또는 네이티브 **wmux**).
2. **director는 버리되 "부품"은 살린다** — **MENTOR**(바텀업 학습), **harvest/watch_live**(가시화)는 어느 하네스에도 얹을 수 있다. 특히 MENTOR는 학습 목표에 핵심.
3. codex의 HEAD 세션 수정은 기술적으로 훌륭했지만, **자동 오케스트레이션을 안 쓰는 이상 그 노력의 목적지가 내 용도와 어긋난다.**
