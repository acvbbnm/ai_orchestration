# 04. 구조적 한계와 개선 시도

## 4.1 근본 한계 — "세션이 안 이어진다 → 매 스텝 콜드스타트"

director의 모든 역할 호출은 **매번 새 프로세스 1회성 호출**이다:
`codex exec -`, `claude --print`. **대화 세션/스레드가 유지되지 않는다.** 그래서:

- 단계마다 **콜드 스타트** — 모델이 직전 자기 추론 위에 쌓지 못하고, `builder_context.py`가 **매번 파일을 통째로 다시 직렬화**해 90k~103k자 프롬프트로 밀어넣는다. 이건 "컨텍스트 엔지니어링"이 아니라 **"파일 덤프"**.
- 수정 루프도 전체를 재전송 → 비싸고 손실이 크다.
- claude가 JSON 깨져 codex로 failover하면 **claude가 하던 작업이 통째로 증발**.

> 체감으로 "계속 바보가 되는" 정체 = **세션 미연속으로 맥락이 매 스텝 풀리는 것.** 이게 director의 가장 깊은 설계 결함이다.

## 4.2 모델별 컨텍스트 엔지니어링 점검 (어댑터 직접 해부)

"하네스/컨텍스트가 모델마다 제대로 적용되나?" → 정직한 답:

| 층위 | 상태 | 근거 |
|---|---|---|
| 그래프·루프·스코프·failover·검증게이트 | ✅ 모델 불문 잘 지켜짐 | 기록(order/review/decision)에 전부 남음 |
| 하네스(각 CLI 구동) | ✅ provider별 맞춤 | codex=exec stdin, claude=--print json, agy=stream-json |
| **모델 선택** | ⚠️ codex/claude **미적용** | `role_settings.py`에 `model='cli-default'` 하드코딩. `--model`은 agy 경로만 |
| **컨텍스트 조립** | ⚠️ 모델 무관 **공통** | `builder_context.py` 단일 예산, `--append-system-prompt` 미사용 |

→ 결론: **"구조"는 모델마다 동일하게 지켜지는데 "모델별 최적화"는 안 돼 있다.** config의 모델값은 강제되지 않고 각 CLI 계정 기본 모델에 의존한다.

## 4.3 개선 시도 ① — 가시화 (내가 만든 도구)

기록이 엔진 폴더에 생 JSON으로만 쌓이고 전부 gitignore라 "뭘 만들었는지" 안 보이는 문제를 해결:

- **`tools/harvest.py`** — 하나의 런을 받아 `Desktop/프로젝트/<작업명>/`로 수확:
  `code/`(worktree에서 회수한 결과물) + `record/`(생 기록 복사) + **`REPORT.md`**(협업 흐름·모델 점검·테스트 결과를 사람 말로 번역) + **git 커밋**. 성공/실패 무관하게 보존(실패 실험도 포트폴리오 가치).
- **`tools/watch_live.py`** — 8081 콘솔이 안 뜰 때 대신 쓰는 **실시간 관전**. 단계 JSON + run.log를 "누가→무엇을" 이벤트로 번역. (03-B의 "123통과/1사전실패"를 이걸로 잡았다.)

## 4.4 개선 시도 ② — MENTOR (바텀업 학습)

AI는 탑다운으로 개발하지만 **나는 바텀업으로 배워야** 한다. 그래서 개발이 끝나면 agy(gemini)가 **나의 학습 포인트**(무엇을 왜 그렇게 했는지, 내가 보강할 개념)를 브리핑하는 MENTOR 역할을 분리해 뒀다(`mentor/`). 개발 자동화와 학습을 **역할로 분리**한 것.

## 4.5 개선 시도 ③ — HEAD 세션 연속성 (codex가 수술)

4.1의 근본 한계를 codex와 함께 수술 중. 핵심:
- **`core/head_sessions.py`** — 프로젝트(정규화 경로)↔Codex 세션ID를 SQLite에 저장. **FileLock 배타 잠금**으로 같은 프로젝트 동시 호출 차단.
- **`agents/codex_head.py`** — 저장된 세션을 `resume <id>` 로 재개(세션ID **UUID 검증**으로 안전), `thread.started`에서 새 세션 저장, 일시 실패(Usage limit)=세션 유지 vs 진짜 소멸(`no rollout found`)=재생성 구분.
- 검증: 새 세션 테스트 **6/6 통과**. A→B→A에서 A의 맥락 유지 + B 안 섞임 + 최신 문서 재주입 + 미션 전체가 HEAD 세션 하나로 이어짐을 확인.

**평가**: 방향이 정석이다 — "엔진을 버리지 말고 **AI 호출부를 세션관리로 교체**, 검증 루프는 유지". 단 **남은 것**:
1. **Builder·Reviewer는 아직 콜드스타트** — 정작 코드를 쓰는 Builder의 연속성이 제일 중요한데 미해결.
2. **Builder의 통짜 JSON 깨짐은 세션과 별개** — 세션 붙여도 안 고쳐진다. **자기 세션 안에서 도구로 파일을 직접 쓰는 방식**으로 가야 근본 해결.
3. **설계 뉘앙스**: Reviewer는 오히려 **연속 세션이 독**일 수 있다. 독립 검수의 "새 눈"은 기능(확증편향 방지)이므로, 세션 대신 **프로젝트 기억(과거 결정)만** 주고 리뷰는 매번 신선하게.
